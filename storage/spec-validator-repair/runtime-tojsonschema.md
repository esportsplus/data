# Runtime toJsonSchema: neutral emitter plus a value-level IR builder

## Rationale

Settled (section I): runtime `toJsonSchema` IS necessary for exactly one reason — `ai-orchestrator` `src/lib/planner/catalog.ts:35` builds `z.enum(skillIds)` from `registry.ids()` at RUNTIME. `src/compiler/json-schema.ts` (277 lines) imports only `type AnalyzedProperty` and `type JsonSchema` — both type-only, fully erased — so it is already pure and runtime-shippable; `generateJsonSchema` is its sole export (by contrast json-schema-constraints.ts imports `ts` and stays compile-time). Settled: move the pure emitter to a neutral module imported by BOTH the compiler and a new `./runtime` subpath, mirroring the `./validators` subpath. The runtime IR producer is the evidence's leading candidate — a small value-level builder constructing the SAME AnalyzedProperty IR.

## Changes

Emitter relocation to a compiler-independent home; a new runtime subpath exporting a minimal schema builder; package exports extended.

## Design

Settled decisions:

- **Neutral emitter home.** `src/compiler/json-schema.ts` moves VERBATIM (post analyzer-schema-gaps) to `src/json-schema.ts`; its mirror test moves `test/compiler/json-schema.test.ts` → `test/json-schema.test.ts` (mirror convention follows the source). Compiler import sites update; `AnalyzedProperty` keeps living in `src/compiler/type-analyzer.ts` and is imported `import type` (erased — runtime-safe by construction, the same fact that makes the emitter pure).
- **Runtime builder (src/runtime/index.ts, new).** A value-level builder constructing AnalyzedProperty IR, surface scoped by the MEASURED consumer need (section J: z.object 52, z.string 45, z.number 27, z.array 5, z.unknown 3, z.record 3, z.union 1, z.enum 1, plus `.default()`): exports `schema` with `object(props)`, `array(element)`, `string()`, `number()`, `boolean()`, `literal(value)`, `enum(values: string[])` (THE driving case), `union(branches)`, `record(value)`, `unknown()`; per-node options object `{default?, description?, nullable?, optional?}` as the modifier channel (no chaining needed at runtime — options-object keeps the builder allocation-light and mirrors the IR 1:1). `toJsonSchema(node)` wraps `generateJsonSchema`. Everything beyond this measured surface is OUT (YAGNI); extending later is additive.
- **Exports.** package.json `exports` gains a `./runtime` entry whose `types` and `default` point at the tsc build output for the new runtime module — exactly the `./validators` entry's pattern, one directory over (build artifacts are generated by `pnpm build`, never hand-edited).
- Discretion point: whether builder nodes are plain object literals typed as AnalyzedProperty or thin creator functions with validation of arguments (e.g. `enum([])` throwing); criterion — invalid builder input fails loudly at BUILD-call time with a module-prefixed error, and the produced IR round-trips through `generateJsonSchema` with zero special-casing (one emitter, two producers stays literally true).

Test plan: `test/json-schema.test.ts` (moved mirror) keeps its emitter coverage at the new path; new `test/runtime/index.test.ts` — `schema.enum(['a','b'])` emits `{enum:['a','b']}`-shaped output (parity with the compile-time literal-union emission, asserted by comparing against a `validator.toJsonSchema<'a'|'b'>()` transform result via test/utils.ts); an object/array/record/union composition with `default` and `optional` emits the same schema the compile-time path emits for the equivalent TS type (parity vectors); `unknown()` and nested nullable behave; builder misuse throws.
